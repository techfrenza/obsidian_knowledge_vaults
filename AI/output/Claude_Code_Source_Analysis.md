# Claude Code 源码分析：AI 编程操作系统的工程架构

---

## 概述

流传的分析材料声称通过约 1900 个文件、超过 51 万行 TypeScript 源码，揭示了 Claude Code 作为"AI 编程操作系统"的底层工程架构。其核心论点是：Claude Code 的竞争优势约 40% 来自模型本身之外的"线束"（Harness）工程——即围绕模型构建的工具治理、上下文管理、多 Agent 协作和提示词系统化设计。

---

## 1. 提示词工程的系统化设计

### 核心声明

- **动态拼装机制**：系统提示词由 `getSystemPrompt()` 函数根据当前 Git 状态、项目约定、MCP 状态等动态组装，而非固定文本。
- **缓存经济学**：通过 `SYSTEM_PROMPT_DYNAMIC_BOUNDARY` 标记，将提示词分为静态段（全局缓存）和动态段（会话特定），最大化 Prompt Cache 利用率。
- **精准指令设计原则**：
  - 负面指令附反例（"不要做 X，例如..."）
  - 量化约束（如"工具调用间文字 ≤25 字"）
  - 价值判断型原则（"三行重复代码优于过早抽象"）
  - 情境-动作决策树（"遇到情境 A → 执行动作 B"）

### 核查结论

**可信度：中等**。动态系统提示词架构与 Claude Code 的实际行为一致（官方文档确认 `CLAUDE.md` 每轮对话重新加载，行为随项目上下文变化）。`SYSTEM_PROMPT_DYNAMIC_BOUNDARY` 这一具体常量名称无法通过官方文档核实，属于源码级细节，未被证伪亦未被证实。精准指令设计原则符合 Anthropic 官方公开的提示词工程建议。

## 2. 上下文与内存管理

### 核心声明

- **五级压缩策略**：微压缩（清理旧工具结果）→ 上下文折叠（总结会话段落）→ 会话记忆提取 → 完全总结 → PTL 截断。
- **自动压缩阈值**：上下文占用超过 95% 时模型性能大幅下降；建议通过 `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE=70` 将触发阈值手动降至 70%。
- **"梦境"记忆架构（Dreaming）**：闲置时唤醒离线 Agent，将原始日志蒸馏为结构化长期记忆。

### 核查结论

**五级压缩策略：可信**。官方文档（`code.claude.com/docs/en/sub-agents`）确认了自动压缩事件（`compact_boundary` 日志条目），与分层压缩机制一致。

**`CLAUDE_AUTOCOMPACT_PCT_OVERRIDE=70`：无法核实**。该环境变量未出现在官方文档的环境变量列表中。可能是源码内部变量，也可能是误传。**不建议依赖此变量**，官方推荐通过 `/compact` 命令手动触发压缩。

**"梦境"架构：无法核实**。官方文档无此描述。这是一个有趣的设计概念，但目前尚无公开证据证明已在生产环境实现。

## 3. 多 Agent 协作架构

### 核心声明

- **协调器-执行者模式**：主 Agent 规划分发，子 Agent 具体执行，两者职责分离。
- **Fork 并行化与缓存共享**：Fork 生成的子 Agent 继承父会话上下文，字节级前缀一致可共享 Prompt Cache，"5 个并行 Agent 成本几乎等同于 1 个"。
- **验证 Agent**：核心指令为"想办法搞坏代码"，主动寻找边界破绽。

### 核查结论

**可信度：高**。官方文档（`code.claude.com/docs/en/sub-agents` 及 Agent SDK sessions 文档）明确支持 `/fork` 命令、`fork_session` API、子 Agent 独立上下文隔离。Fork 会话复用历史上下文（即前缀缓存复用）是 Anthropic API Prompt Cache 的已知机制，原理可信。

**"5 个并行 Agent 成本等同于 1 个"**：这是对缓存命中率的乐观估计，实际节省比例取决于动态段占比，原文表述略有夸张，但底层机制属实。

**验证 Agent 的"搞坏代码"指令**：与官方多 Agent 最佳实践（实现者与验证者分离）一致，可信。

## 4. 工具治理与安全防御

### 核心声明

- **先读后改原则**：`FileEditTool` 强制要求模型先调用读取工具，否则报错。
- **YOLO 分类器**：用小型 LLM 作为安全门禁，预判 Bash 命令风险（Allow / Soft Deny / Hard Deny）。
- **反蒸馏防护**：在 API 请求中注入伪造工具定义（Decoy tools），针对竞品窃取流量训练。
- **`PreToolUse` / `PostToolUse` Hooks**：执行拦截与自动化检查。

### 核查结论

**Hooks 系统：完全核实**。官方文档详细描述了 `PreToolUse`、`PostToolUse`、`SessionStart` 等 25+ 生命周期事件，配置于 `.claude/settings.json`，确定性执行。

**先读后改原则：可信**。与官方 Edit 工具的使用规范一致（工具说明要求先 Read 再 Edit）。

**YOLO 分类器：无法核实**。这是源码级实现细节，官方无公开说明，但从工程角度合理。

**反蒸馏 Decoy Tools：无法核实，存疑**。此说法较为罕见，官方无任何公开确认。作为竞争性安全措施，即使存在也不会公开披露，但目前证据不足，应视为未证实声明。

## 5. 高级功能与隐藏特性

### 核心声明

- **KAIROS**：永远在线、主动触发任务的助理。
- **ULTRAPLAN**：长达 30 分钟的云端深度规划。
- **Speculation**：预测用户下一步操作并提前在沙箱预执行。
- **卧底模式（Undercover Mode）**：在公共仓库工作时隐去 AI 生成迹象及内部代号（Capybara, Tengu）。
- **电子宠物（Buddy）**：基于用户 ID 确定性生成的虚拟宠物，作为用户留存机制。

### 核查结论

**无法核实，属于未发布特性传言**。这五项均未出现在任何官方文档中。内部代号（Capybara, Tengu）是 Anthropic 项目代号的常见风格，存在合理性，但具体功能描述无法验证。**应视为待证实的二手分析结论**，而非已确认的工程事实。
