## 技术核心逻辑

结构化 Prompt 的三元组公式（[[Prompt_Template_Library]]）：
```
专家级输出 = 结构化角色 + 约束规则 + 输出格式
```

这个公式在**执行类任务**效果卓越（代码审查、架构建议、决策矩阵），原因是：约束减少了搜索空间，使模型注意力聚焦于预定义路径。

但在**创意类任务**（创业想法、非常规解法、突破性分析），同样的约束会：
- 将输出锚定在模板定义的期望范围内
- 过滤掉格式外的关联跳跃（Associative Leap）
- 让模型优化"符合格式"而非"生成最好的想法"

## 优缺点对比

| 任务类型 | 结构化Prompt | 开放式Prompt |
|---------|-------------|-------------|
| 执行（代码审查/报告） | 最优——格式即质量标准 | 次优——需后处理 |
| 分析（决策矩阵/SWOT） | 最优——框架驱动完整性 | 遗漏率高 |
| 创意（想法/突破性洞察） | **劣势**——格式即天花板 | 最优——允许意外发现 |
| 学习（理解概念） | 中等——有助结构化理解 | 中等——允许探索性 |

**设计原则**：在任何会话开始前，先判断任务类型。执行类 → 最大化结构；创意类 → 最小化约束，只保留角色定义，去掉输出格式。

**跨模型注意**：[[Prompt_Template_Library]] 指出"模板在 Claude 上表现最优，GPT/Gemini 的 CoT 触发机制略有差异"——结构化 Prompt 还有模型锁定风险。
