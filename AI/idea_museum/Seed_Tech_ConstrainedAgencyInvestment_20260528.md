# 约束即授信：Constrained Agency 的反直觉积累逻辑

## 技术核心逻辑

企业 Agent 两种启动策略：

**A. 自由起步**：给 Agent 广泛权限，"用可用工具帮用户处理未结项"
- 优点：快速上线
- 缺点：行为不可测，测试不可写，出错无法归因

**B. 约束起步（SAP 推荐）**：精确步骤指令，限制工具集，明确参数范围
```
STEP 1: 从请求提取公司代码/财年/清账日期
STEP 2: 调用 get_open_items（传公司代码+财年）
STEP 3: 展示结果并请求确认
STEP 4: 仅对已确认项调用 execute_clearing
```

## 反直觉权衡

| 维度 | 自由起步 | 约束起步 |
|------|---------|---------|
| 初始能力感 | 高（能处理更多场景） | 低（只处理定义场景） |
| 可测试性 | 极低 | 高（步骤可独立验证） |
| 扩权路径 | 随机（无法积累证据） | 系统化（每步成功=授信记录） |
| 生产风险 | 高（意外行为无法预测） | 低（边界物理可执行） |

## 深度洞察

"更多自主权是长期目标——通过验证的生产行为逐步赢得，而非假设得来。"约束不是能力限制，是信任协议的第一章。无约束的 Agent 永远无法通过企业合规审查，因为它无法提供"它为何做了某件事"的确定性证明。

从约束到自主的路径：约束行为 → 可观测测试 → 通过率积累 → 边界扩展 → 更大约束下的更多自主权。自由度是线性赢得的，不是一次性给予的。
